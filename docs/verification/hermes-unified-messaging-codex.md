Root owns native migration generation, CoreEngine/metadata wiring, CI and deployment; peers own WA/IMAP/MCP adapters and frontend.

Implemented: two normalized persistent core entities; composite tenant FK from message to conversation; scoped unique provider identities and workspace-wide outbound command IDs; authenticated metadata list/message/connection APIs; explicit reply and bot-draft mutations; pluggable runtime adapter/bot registry. Provider IDs and cursor values are bounded/validated; plain text is capped at 20,000 characters. Opaque date+ID pagination retains equal-timestamp rows. No public event ingestion or workspace input grants access.

Ingress rechecks active/nondeleted workspace inside the actual database transaction and serializes replays with a workspace-scoped PostgreSQL advisory transaction lock. Event replay returns its durable identity; changed payload under a reused identity conflicts. Timestamp differences between receipt/webhook are tolerated. Body/status are stored in PostgreSQL rather than an in-memory inbox. A contact-handle change retains the received message with an explicit review error, hides the automatic CRM match and blocks replies until resolution; it never silently retargets a conversation.

Replies reserve an UNCONFIRMED row before any provider send, keyed by workspace/clientRequestId and a digest including destination conversation and text. Concurrent/repeated client requests cannot initiate a second send; changed content/destination conflicts. A receipt yields ACCEPTED, not delivered. Timeout/unknown POST failure or failed acceptance persistence keeps a durable uncertain reservation. Provider echoes/receipts reconcile to one visible canonical provider message. An uncertain send with no provider ID cannot safely be auto-correlated solely from matching text and is never retried automatically. Core does not initiate any scheduled/retry sends.

Authorization uses the existing fresh native membership/unrestricted-admin boundary plus an additional fresh role-object-permission denial check, without modifying prospection's owned service. Person matching uses native UserRoleService + repository role intersection, not a permissions bypass, and the native canonical email/phone query utility. Archived/ambiguous contacts are not linked or created. Only explicitly ingested shared connections are visible; no private mailbox discovery. Core-native messaging was evaluated; native timeline/message projection is deferred so mail-channel/S3/feature provisioning cannot discard received core events.

Registry exports register(adapter), registerBot(adapter), get/getBot, with duplicate registration refusal. Optional adapter/bot DI tokens are supported, but parent-module providers are not automatically visible in child Nest modules: root adapter modules should import HermesMessagingModule and register their providers on initialization. Missing adapter/bot is NOT_CONFIGURED. CONFIGURED_UNVERIFIED is distinct from provider-confirmed AVAILABLE; capability flags are forced false for unavailable/unconfigured states. Bot draft receives only the scoped persisted message; it never dispatches. Actual connection/protocol availability remains the adapters' responsibility.

Validation: 26 Jest tests pass in four suites.
