## Implemented first slice

Metadata GraphQL uses the same standard tenant-bound user session guard as the existing inbox, denies API key/application/impersonation, and rechecks the current unrestricted administrator role. Workspace/user/membership always come from the session. The account is resolved through the existing server binding and native encrypted ConnectedAccount; absent configuration is not a connection proof.

- `hermesMailFoldersV4: JSONObject!` returns `{state,folders:[{path,name,role,total,unread}]}`. Roles INBOX/SENT/DRAFTS/ARCHIVE/TRASH/CUSTOM derive from native IMAP special-use flags. Unknown counts are null. Nonselectable folders excluded; no fabricated zero or folder.
- `hermesMailMessagesV4(input:HermesMailPageInput!): JSONObject!`, `{folder,limit?:1..50,cursor?:string}` returns `{state,folder,uidValidity,messages:[{uid,subject,from,to,cc,occurredAt,seen,size}],nextCursor}`. UID pagination newest first; cursor binds the folder and UIDVALIDITY. A mailbox reset fails `MAIL_CURSOR_EXPIRED`; refresh from first page.
- `hermesMailMessageV4(input:HermesMailMessageInput!): JSONObject!`, `{folder,uid,uidValidity}`. Native bounded MIME read, text+allowlisted HTML, remote image sources/CSS/forms/scripts/SVG removed. Bcc only visible to the bound mailbox owner. Attachment metadata has `state:REQUIRES_PRIVATE_IMPORT` until the B scoped native-file import is integrated; never use metadata as an enabled download action.
- `hermesMailUpdateV4(input:HermesMailUpdateInput!): JSONObject!`, scope above plus `{seen?:boolean,destination?:string}`. Uses native flag add/remove and move to an existing selectable folder; no permanent-delete operation.
- `hermesMailPlanV4(input:HermesMailComposeInput!): JSONObject!`, scope plus `{mode:REPLY|REPLY_ALL|FORWARD,from,to?,cc?,bcc?,text,html?,conversationId?,clientRequestId?,attachmentIds?}`. Resolves original MIME server-side; Reply-To preference, case-insensitive own-address exclusion and To/CC/Bcc deduplication, never copies received Bcc, forwards without reply references. Exact mailbox sender required in first slice; same-domain substitution rejected. Returns `{state:PLANNED,envelope}` for preview, no emission.
- `hermesMailSaveDraftV4(input:HermesMailComposeInput!): JSONObject!`: compiles native MailComposer MIME and appends to the provider's real special-use Drafts folder with `\\Draft`. Returns `{state:SAVED,folder,uid,uidValidity}`; no SMTP call. Missing provider/drafts folder fails explicitly. First slice rejects attachment IDs until scoped byte assembly is connected.

Existing `hermesInboxSyncEmail` and messaging v1 remain compatible. These signatures are additive. Read-only inbox APIs use Query; commands use Mutation. `MAIL_NOT_CONFIGURED`, `MAIL_TIMEOUT`, UID validity/permission/scope errors are errors, not empty mailboxes or synthetic success.

## Coordinated B integration (in progress)

`messaging.replyEmail(actor,{conversationId,clientRequestId,envelope,attachmentIds})` reserves all attachments atomically in B's durable ledger and rechecks role/policy before provider call. C owns exact sender/recipient/MIME preparation and passes an envelope plus private byte attachments to the existing SMTP adapter. No direct-send endpoint may bypass this method. Timeout/UNCONFIRMED must reuse the original request ID and must never trigger a blind retry/new ID. ACCEPTED means SMTP acceptance, not delivered/read.

B native media supports FILE and EMAIL conversation scopes, max10 attachments/25MiB total, each PDF/DOCX/XLSX/PPTX ≤20MiB or supported image format. Incoming MIME remains bounded to36MiB (base64 overhead included). Read assets through session-bound private `hermesMediaRead`; no provider/static URL. Forwarding clones through `cloneForConversation` after both source and target authorization. CID metadata may reference only private scoped imported image assets; no arbitrary cid/data/http source is enabled. This integration and native protocol tests must pass before enabling rich sending/downloads in UI.

### Editable native draft identity (C4)

`HermesMailNewDraftInput` adds optional UUID `draftId` and optional64hex `draftRevision`. Create/save uses `draftId` as stable identity; legacy clientRequestId remains the fallback. Blank To/CC/Bcc, subject and text are valid for saving. From must still be the exact connected identity/verified alias. Return `{state:SAVED,draftId,draftRevision,conversationId,folder,uid:String,uidValidity:String,replay}`. Native content is re-read for compare-and-swap; a stale supplied revision rejects before retargeting the canonical conversation. Identical content replays without APPEND. Edited content appends with stable native Message-ID then moves only replaced UIDs to the actual LIST Trash folder. No global EXPUNGE or permanent-delete API. Missing Trash blocks replacement; missing APPEND UID/UIDVALIDITY yields explicit unconfirmed save, never a false saved result.

Native Redis serializes the stable draft identity for60s, exceeding the45s native session deadline. Existing B conversation is retargeted only while UNSENT; any outbound send reservation freezes further drafts (including UNCONFIRMED and FAILED). Retarget clears delegated bot grants and keeps OFF. Current canonical contact drives native person matching; no prospect/opportunity is auto-created. Private Bcc-only drafts use own From as public contact. Attachments remain scoped to the same conversation across edits.

SendNew takes both `draftId` (existing canonical draft) and a separate `clientRequestId` (immutable send attempt). Save changed recipients/subject before sending. Every send goes through B.replyEmail reservation/authorization; replay the exact same request id and content after uncertainty, never change a reserved envelope or invent a new retry id. Sent-copy acceptance remains a separate pending slice.

### Native Sent copy and receipt reconciliation (C5)

Rich send/reply returns the existing B message with `sentCopy:{state:SAVED|UNAVAILABLE|UNCONFIRMED|NOT_ACCEPTED,reason?,replay?,folder?,uid?,uidValidity?}`. Send `status:ACCEPTED` always reflects the existing SMTP receipt ledger; it is independent of native-copy storage. The module searches the actual LIST Sent folder for the deterministic Message-ID and compares exact sender, To/CC, normalized text/sanitized HTML and complete attachment bytes/names/types. Provider-added Received/Date headers are ignored. An absent provider Bcc header is tolerated; a different Bcc is never accepted or exposed as public metadata. Matching provider auto-copy is reused; newly appended copies are read back before association.

Before any APPEND, the canonical ACCEPTED message reserves `providerMetadata.sentCopyState:PENDING` durably under the existing workspace ledger lock with same-manager role/current D revision/deadline checks. Failed/lost ACK records UNCONFIRMED; PENDING/UNCONFIRMED/SAVED allows subsequent search/reconciliation only, never blind APPEND. An accepted send is never retried because native Sent storage failed. This does not claim exactly-once IMAP on providers without that capability. A proven native-copy full SHA reuses the original accepted canonical message and attachment IDs when read; it never fabricates acceptance from From/Message-ID headers. No Bcc/raw MIME is stored in public metadata.

### Automatic responder loop guard

Native MIME observation returns `autoReplyBlockedReason` separately from manual bot/draft capabilities. Non-human Auto-Submitted (valid parameters recognized), null Return-Path, bulk/list headers and delivery-status reports suppress AUTO before MCP; they remain readable and manually actionable under current policy. B ingests the bounded metadata reason defensively. Only an internal validated bot grant sets adapter `automated:true`; C SMTP marks those responses `Auto-Submitted:auto-replied`. Human sends, including approved MCP drafts, omit that header. No public input enables automated provenance.

A stable draft with an existing outbound reservation cannot be sent under a new request id to bypass uncertainty. Reuse the original immutable clientRequestId and unchanged content; B returns its stored outcome. Verified alias changes preserve draft identity. Reply References keep the original thread root and latest ids within the existing20-reference ledger limit.
