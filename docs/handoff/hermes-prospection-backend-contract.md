# Hermes B2B backend contract

Implementation: `HermesProspectionModule` in the existing Nest/metadata GraphQL server, not a separate API. Authentication is the existing signed-in user session and selected workspace. Do not send a workspace ID supplied by the browser: the resolver derives it from authenticated context. This first delivery is restricted to live workspace members with unrestricted workspace-administrator permissions; API keys, apps and impersonated/playground sessions are refused.

## Metadata GraphQL operations

All four return GraphQLJSONObject. Inputs are typed GraphQL InputTypes (unknown fields rejected) and validated by ResolverValidationPipe.

- `hermesImportBatches`: `{ version:1, batches:HermesImportBatch[], campaignIds:string[], capabilities:{smtpCampaignSending:false,trackingDefault:false,nativeCampaignDrafts:true} }`.
- `hermesCreateImportBatch(input: HermesCreateImportBatchInput!)`: `{batch:HermesImportBatch,replay:boolean}`. Input `{externalBatchId,name,sourceUrl,collectedAt,rows:[{email,companyName,firstName?,lastName?,jobTitle?,website?,phone?}]}`. Maximum 100 rows/batch, 40 retained batches/workspace and 2 MB state. CollectedAt is ISO8601; source URL http(s), no embedded credentials. Replaying the same externalBatchId and normalized source content returns the same IDs. Different content under the same external ID conflicts. Rows are staged even when their email/company/website validation fails; errors are returned per row.
- `hermesQualifyImportRows(input: HermesQualifyImportRowsInput!)`: `{batchId,rows:HermesImportRow[]}`. Input `{batchId,rowIds,professionalPurpose,privacyNoticeUrl,informationMethod:'already-informed'|'first-contact-notice'}`. Maximum 100 unique row IDs. PrivacyNoticeUrl must use HTTPS. Purpose is 8–1000 characters. Creates or reuses native Company/Person records under the acting user's effective permissions. Primary and additional emails are matched case-insensitively, archived/ambiguous/inconsistent records require review. Existing contact fields are preserved; website and phone remain provenance fields in staging, not silently mapped into unverified contact composites.
- `hermesCreateCampaignDraft(input: HermesCreateCampaignDraftInput!)`: `{campaignId,listId,status:'DRAFT',sendingAvailable:false}`. Input `{name,subject,rowIds}` (maximum 100). Only qualified, unsuppressed recipients whose current primary email matches the staged email are eligible. Creates native messageCampaign/messageList/messageListMember records atomically. The same normalized request reuses deterministic IDs. Native campaign feature flag and email-group access remain enforced. No send action occurs.

HermesImportBatch: `{id,externalBatchId,fingerprint,name,sourceUrl,collectedAt,createdAt,createdByUserId,rows}`. HermesImportRow: source fields plus `{id,status,errors:string[],personId?,companyId?,qualification?}`. Status: pending / invalid / duplicate / suppressed / qualified / conflict. Qualification records purpose, notice URL, information method, timestamp and actor.

## Existing native functionality reused

Existing EmailingModule owns campaigns, audience lists, queues, send/materialization jobs, delivery events, campaign statistics, suppressions, unsubscribe preference pages and opaque unsubscribe tokens. Existing public unsubscribe GET renders preferences; existing POST applies durable opposition. Native suppressions are authoritative on staging, reimport, qualification and draft creation. Tracking-only suppression does not itself block marketing sending. No code here removes suppressions.

Native open/click tracking defaults are false on WorkspaceEntity. No send means no tracking artifact is generated by these operations. `smtpCampaignSending:false` describes this delivered bridge: native emailing drivers at its baseline are AWS_SES, RESEND and LOG, with no SMTP campaign adapter. Native statistics distinguish accepted, delivered and observed opens; an open is not proof that a person read an email. SMTP and tracking activation require the separate integration work and configured synthetic tests; no real recipients were contacted.

## Activation and verification

Root integration must import HermesProspectionModule into CoreEngineModule and generate/register the current 2.52 reversible instance command for the new `core.hermesImportState` entity using the repository generator against an isolated baseline DB. Do not hand-edit the generated migration manifest. Durable state is row-locked per workspace; foreign key cascades on workspace deletion. Native ORM writes and core staging use separate transactions: stable IDs/email matching recover an interrupted qualification, deterministic campaign/list IDs recover an interrupted campaign draft. Concurrent manual edits remain protected by native ORM permissions and database constraints.

Pure-policy tests cover normalization, duplicate rows, idempotency conflict, workspace-independent state, retention bounds and unsafe source metadata. Further access/suppression tests and full type/build validation are being completed before integration. No external Hermes scraper, WhatsApp gateway, native app or credential storage is introduced here.
